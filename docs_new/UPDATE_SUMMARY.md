## 2025-12-09: 系统定位重大升级 - 从垂直工具到通用平台 ⭐ 新增

### 🎯 升级概述

**系统定位演进**：
```
V1.0: K12教育内容生成·元工作流系统
       ↓
V2.0: 通用领域内容生成·元工作流平台 ⭐
```

**核心理念**：孵化器-鸡-蛋模型
- **孵化器**：元工作流引擎（通用基础设施）
- **鸡**：领域适配器（K12、美术史、畅销书、职业培训等）
- **蛋**：生成的内容产物（课件、讲稿、笔记、培训材料等）

### 背景与动机

**原定位的局限性**：
- 仅服务K12教育领域，市场覆盖有限
- 依赖预设的学习目标和知识库，不支持模糊需求
- 内容呈现以"知识点+例题"为主，缺乏吸引力

**新需求驱动**：
1. **多领域扩展需求**：
   - 美术史教育（名画讲解、艺术史）
   - 畅销书解读（精读笔记、读书会）
   - 职业培训（Excel、编程、技能培训）
   - 企业培训（管理、合规、技术培训）
   - 通识教育（历史、哲学、科普）

2. **AI能力升级需求**：
   - **AI生成目标**：从模糊需求自动推断学习目标
   - **AI内容发现**：实时从多源检索和整合内容
   - **故事化叙述**：将枯燥内容转化为引人入胜的故事

3. **平台化需求**：
   - 一套系统服务多个行业
   - 快速扩展新领域（插件化架构）
   - 降低边际成本，扩大市场规模

## 2025-12-09: 自动化工作流构建与优化系统 ⭐ 新增

### 背景与动机

在智能模板推荐系统（3.2.1）的基础上，我们发现了更进一步的需求：

1. **模板库覆盖不足**：对于新兴课型、跨学科融合、特殊教学法等场景，现有模板库可能没有合适的模板
2. **创新需求无法满足**：教师希望尝试新的教学方式（如VR沉浸式教学、游戏化学习），但现有模板无法直接支持
3. **从复用到创造**：不仅要"找到现成的"，更要能"从0创造新的"

**核心问题**：如何让系统不仅能**推荐现有模板**，还能**自动构建全新的工作流**？

### 解决方案

实现了一个**AI驱动的工作流自动构建系统**，能够根据用户需求从组件级别开始，自动设计、构建、测试和优化工作流，并通过迭代循环不断提升质量。

##### **整体架构（7个核心组件）**

##### **1. 组件注册表 (Component Registry)**

**目的**：维护所有可用组件的能力描述，供工作流编排器查询和选择

**核心数据结构**：
```python
@dataclass
class ComponentCapability:
    component_id: str           # 组件ID
    component_name: str         # 组件名称
    category: str              # generator/transformer/evaluator/tool
    description: str           # 功能描述
    use_cases: List[str]       # 适用场景
    input_schema: Dict         # 输入规范
    output_schema: Dict        # 输出规范
    required_params: List[str] # 必需参数
    optional_params: Dict      # 可选参数
    examples: List[Dict]       # 使用示例
    dependencies: List[str]    # 依赖组件
    constraints: Dict          # 使用约束
    tags: List[str]           # 搜索标签
```

**核心功能**：
- `search_by_capability()`: 基于能力描述搜索组件（语义搜索+规则过滤）
- `validate_workflow()`: 验证工作流配置的合法性
- `get_by_category()`: 按类别获取组件

**实现**：`ComponentRegistry` 类，完整代码示例

##### **2. 需求分析器 (Requirement Analyzer)**

**目的**：将用户的自然语言需求转化为结构化的工作流设计约束

**核心流程**：
```
用户输入（自然语言）
    ↓
LLM信息提取（使用JSON mode）
    ↓
结构化需求对象（WorkflowRequirement）
    ↓
交互式澄清（识别缺失字段）
```

**结构化输出**：
```python
@dataclass
class WorkflowRequirement:
    subject: str                              # 学科
    grade: str                                # 年级
    topic: str                                # 主题
    region: str                               # 地区
    learning_objectives: List[str]            # 教学目标
    content_requirements: List[ContentReq]    # 内容需求
    workflow_steps: List[WorkflowStep]        # 流程步骤
    constraints: Dict                         # 约束条件
    evaluation_criteria: List[str]            # 评估标准
```

**实现**：`RequirementAnalyzer` 类，支持交互式需求完善

##### **3. 工作流编排器 (Workflow Composer)**

**目的**：根据需求分析结果和组件注册表，自动设计工作流DAG

**核心算法：基于能力匹配的DAG构建**

**编排流程**：
```
1. 为每个步骤选择组件（规划节点）
   - 搜索满足required_capabilities的组件
   - 使用LLM从候选中选择最佳组件
2. 构建节点配置
   - 使用LLM生成定制化提示词（meta-prompt技术）
   - 根据需求自动设置参数
3. 分析依赖关系，构建边
4. 验证DAG合法性（无环、连通性检查）
5. 组装完整工作流
```

**关键技术**：
- **Meta-Prompt生成**：使用LLM为每个组件生成专用提示词
- **自动参数推断**：根据年级推断难度等级等
- **DAG验证**：DFS检测环、检查孤立节点

**实现**：`WorkflowComposer` 类，包含节点规划、配置生成、边构建等完整逻辑

##### **4. 试运行执行器 (Trial Executor)**

**目的**：执行新构建的工作流，收集输出结果用于评估

**核心功能**：
- 执行工作流（启用完整日志和中间结果收集）
- 生成模拟输入数据（如无提供）
- 收集执行信息（节点输出、执行时间、错误信息）

**实现**：`TrialExecutor` 类，返回 `TrialResult` 对象

##### **5. 质量评估器 (Quality Evaluator)**

**目的**：分析试运行结果，诊断问题并给出优化建议

**评估策略：三种模式**
- **auto**：使用LLM自动评估（5个维度）
- **human**：人工交互式评估
- **hybrid**：自动+人工混合评估

**自动评估维度**：
1. 内容准确性（是否符合知识点要求）
2. 难度适配性（是否符合年级水平）
3. 逻辑连贯性（内容之间的逻辑关系）
4. 教学有效性（是否能达成教学目标）
5. 语言表达（是否清晰易懂）

**问题诊断**：
- 按严重程度分类：critical / major / minor
- 按类别分类：content / structure / language / performance
- 为每个问题生成改进建议

**实现**：`QualityEvaluator` 类，返回 `EvaluationReport` 对象

##### **6. 工作流优化器 (Workflow Optimizer)**

**目的**：根据评估报告自动调整工作流配置

**六种优化策略**：
1. **调整提示词**：针对内容质量问题，使用LLM改进prompt
2. **修改组件参数**：调整temperature、难度等级等
3. **更换组件**：当组件能力不足时，替换为更合适的组件
4. **增加节点**：补充缺失的处理步骤（如质量检查）
5. **删除节点**：移除冗余或低价值节点
6. **调整连接**：修复逻辑顺序问题

**优化决策逻辑**：
- 按问题严重程度排序（critical > major > minor）
- 根据问题类别选择优化策略
- 使用LLM进行复杂决策（如提示词改进）

**实现**：`WorkflowOptimizer` 类，包含多种优化方法

##### **7. 迭代控制器 (Iteration Controller)**

**目的**：管理整个"构建-试运行-评估-优化"的循环过程

**迭代流程**：
```
1. 初始构建（使用 Workflow Composer）
2. 循环迭代（最多 max_iterations 次）：
   a. 试运行（Trial Executor）
   b. 质量评估（Quality Evaluator）
   c. 判断收敛：
      - 评分 >= convergence_threshold → 成功结束
      - 达到最大迭代次数 → 结束
   d. 优化工作流（Workflow Optimizer）
3. 返回最终工作流和迭代历史
```

**收敛判断**：
- 默认阈值：0.8（可配置）
- 综合考虑评分和通过状态

**版本管理**：
- 记录每轮迭代的完整状态
- 支持回溯到最佳版本
- 提供迭代历史分析

**实现**：`IterationController` 类，支持自动迭代和交互式优化

## 2025-12-09: 智能模板推荐匹配系统 ⭐ 新增

### 背景与动机

1. **需求表达模糊**：教师可能只知道"我要讲分数加法"，但不清楚具体需要什么样的模板
2. **模板数量众多**：系统中可能有数百个模板，手动筛选效率低下
3. **个性化需求**：不同教师有不同的教学风格和偏好
4. **质量参差不齐**：需要综合考虑模板的执行成功率、用户评分等质量指标

### 解决方案

实现了一个**三层混合推荐系统**，结合规则匹配、语义检索和协同过滤，提供精准、个性化、可解释的模板推荐。

##### **三层匹配策略**

**第一层：规则匹配层 (Rule-based Matching)**
- **目的**：快速过滤出符合硬性条件的候选模板
- **匹配规则**：
  * 学科匹配（必须）：支持学科别名映射
  * 年级范围匹配（必须）：检查查询年级是否在模板范围内
  * 地区匹配（可选，+15分）
  * 课型匹配（可选，+10分）
  * 标签匹配（可选，每个标签+5分）
  * 语言匹配（可选，+10分）
- **评分机制**：总分0-100，按分数排序
- **实现**：`TemplateRuleMatcher` 类，完整代码示例

**第二层：语义检索层 (Semantic Search)**
- **目的**：基于关键词、描述的语义相似度，找到概念上相关的模板
- **技术方案**：
  * 向量数据库：Milvus / Qdrant
  * Embedding模型：OpenAI text-embedding-3-small / BGE-M3
  * 检索策略：混合检索（向量 + BM25）
- **核心流程**：
  1. 构建查询文本（学科+年级+课型+关键词+描述）
  2. 生成查询向量（Embedding）
  3. 向量检索（ANN - Approximate Nearest Neighbor，余弦相似度）
  4. BM25关键词检索（可选）
  5. 结果合并（Reciprocal Rank Fusion - RRF算法）
- **向量化策略**：模板入库时生成embedding（模板名称+学科+年级+描述+标签+教学目标+适用场景）
- **实现**：`TemplateSemanticSearchEngine` 类，完整代码示例

**第三层：协同过滤层 (Collaborative Filtering)**
- **目的**：基于用户行为数据，提供个性化推荐
- **策略**：
  * **Item-based CF**（基于物品）：找到与用户历史使用模板相似的模板
  * **User-based CF**（基于用户）：找到相似用户喜欢的模板
- **相似度计算**：
  * 模板相似度：基于共现矩阵（同一用户使用过的模板）
  * 用户相似度：Jaccard相似度（使用模板的重叠度）
- **冷启动处理**：无历史数据时返回热门模板（按使用次数和评分排序）
- **实现**：`CollaborativeFilteringRecommender` 类，完整代码示例

##### **综合排序与评分**

**加权综合分数**：

```
final_score =

  + 0.15 × quality_score       (模板质量)
  + 0.05 × popularity_score    (流行度)
```

**质量分数计算**：

- 平均质量评分（30%权重）
- 用户评分（30%权重）

### 2. 版本控制算法

**自动版本号递增**:
```python
def _increment_version(current_version: str, modifications: Dict) -> str:
    major, minor, patch = map(int, current_version.split("."))
    
    if has_breaking_change(modifications):
        return f"{major + 1}.0.0"  # 主版本号+1
    elif has_new_feature(modifications):
        return f"{major}.{minor + 1}.0"  # 次版本号+1
    else:
        return f"{major}.{minor}.{patch + 1}"  # 修订号+1
```

### 3. 优化建议生成

**性能分析算法**:
```python
def _analyze_performance(records: List[Dict]) -> List[Dict]:
    node_durations = defaultdict(list)
    for record in records:
        for node in record["execution_trace"]["nodes"]:
            node_durations[node["node_id"]].append(node["duration"])
    
    suggestions = []
    for node_id, durations in node_durations.items():
        avg_duration = sum(durations) / len(durations)
        if avg_duration > THRESHOLD:
            suggestions.append({
                "issue": f"节点平均耗时{avg_duration:.1f}秒",
                "suggestion": "建议优化或增加缓存"
            })
    return suggestions
```
